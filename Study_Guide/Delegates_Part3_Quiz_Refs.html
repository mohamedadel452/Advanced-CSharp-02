2) تصحيحات وملاحظات على السلايدات

  1. سلايد 25: "Lambdas are syntactic sugar over anonymous methods". غير دقيق، الـ lambda تتحول لـ Expression Tree والـ anonymous method لأ، وفي natural type (جزء 2 قسم 3).
  2. سلايد 4: "function pointer": تبسيط. الـ delegate object بيحمل Target و Method، وده سبب الـ memory leak (جزء 1 قسم 7).
  3. سلايد 7 و 8: "signature must match exactly": ما فيهاش ذكر لـ variance للـ reference types (جزء 1 قسم 4).
  4. سلايد 5 و 6: نفس المحتوى مكرر.
  5. سلايد 26: سؤالين Generics (Print<T> و Echo<T>) منقولين من جلسة تانية وخارج موضوع الـ Delegates. ونفس الإشكالات اللي ذكرتها قبل كده (الإجابة 100 C# في سطر واحد بينما الناتج سطرين).
  6. أسئلة سلايد 20 و 21 و 31 و 32: عدة أسئلة فيها أكتر من إجابة صحيحة (⚠ فوق)، وكلها من غير مفتاح إجابة. ما تحفظش حرف الإجابة، افهم السبب.

3) أسئلة مقابلات شائعة على الموضوع

السؤالإجابة مختصرة تظهر العمق
إيه الـ delegate داخلياً؟class مولّد يرث MulticastDelegate فيه Target و Method و invocation list، reference type و immutable.
الفرق بين delegate و event؟الـ event بيقيّد الوصول من برّه: += و -= بس، ومفيش استدعاء أو تعيين من خارج الـ class.
إيه بيحصل لو multicast delegate بيرجع قيمة؟آخر دالة هي اللي تتحفظ نتيجتها، والباقي يضيع. استخدم GetInvocationList().
إزاي ممكن delegate يسبب memory leak؟الاشتراك في event لـ publisher طويل العمر بيخلي الـ Target (الـ subscriber) محجوز من الـ GC.
الفرق بين Func و Predicate؟Predicate يرجع bool وbاراميتر واحد، وFunc<T,bool> هو المعيار في LINQ، وهما نوعين غير قابلين للتحويل الضمني.
إيه الـ closure؟lambda بتمسك متغيرات من الـ scope اللي حواليها بالمرجع، والمترجم بيرفعها لحقول في class على الـ Heap.
ليه for بيدي 3 3 3 و foreach لأ؟متغير الـ for واحد لكل الحلقة، وforeach بيعمل متغير جديد لكل دورة منذ C# 5.
Func مقابل Expression<Func>؟الأول كود قابل للتنفيذ، والتاني شجرة بيانات تتحول لـ SQL في EF. استخدام Func على IQueryable بيجيب الجدول كله.
إيه الخطر في async lambda مع Action؟بتبقى async void: مفيش انتظار والأخطاء ممكن تقفل الـ process. استخدم Func<Task>.
إمتى أفضّل interface على delegate؟لما العقد أكتر من دالة، أو محتاج تسجيله وحقنه في الـ DI.

  • C# Delegates, Actions, Events: summary (Medium): الرابط ده جه ذكره في إجابة على Microsoft Q&A كملخص للـ delegates والـ events، ومافتحتوش بنفسي.

6) تمرين تطبيقي: Order Pipeline بالـ Delegates

ابني pipeline لمعالجة طلب، كل خطوة delegate، بحيث تضيف خطوة جديدة من غير تعديل الـ pipeline نفسه.

public record Order(int Id, decimal Total, string Status = "New");

public class OrderPipeline
{
    private readonly List<(string Name, Func<Order, Task<bool>> Step)> _steps = new();

    public OrderPipeline Add(string name, Func<Order, Task<bool>> step) { _steps.Add((name, step)); return this; }

    public async Task<(bool Ok, string? FailedAt)> RunAsync(Order o)
    {
        foreach (var (name, step) in _steps)
            if (!await step(o)) return (false, name);     // يوقف عند أول فشل
        return (true, null);
    }
}

var pipeline = new OrderPipeline()
    .Add("Validate", o => Task.FromResult(o.Total > 0))
    .Add("Charge",   async o => { await Task.Delay(50); return o.Total < 10_000; })
    .Add("Notify",   o => { Console.WriteLine($"Order {o.Id} done"); return Task.FromResult(true); });

Console.WriteLine(await pipeline.RunAsync(new Order(1, 500)));       // (True, )
Console.WriteLine(await pipeline.RunAsync(new Order(2, 50_000)));    // (False, Charge)

مطلوب منك:

  1. أضف خطوة Logging تتنفذ قبل وبعد كل خطوة (فكّر: دالة بتاخد Func وترجع Func يلفّها).
  2. غيّر الـ pipeline ليتجاهل الخطوات اللي بترمي exception ويسجلها بدل ما يقف، باستخدام try/catch داخل الحلقة.
  3. أضف Retry (من الجزء 2) على خطوة Charge فقط.
  4. حوّل الـ pipeline لـ events: event Action<string>? StepFailed واشترك فيه، وبعدها اشرح لنفسك ليه لازم تفك الاشتراك.
  5. اكتب اختبار يثبت إن خطوة Notify ما بتتنفذش لو Charge فشلت.
